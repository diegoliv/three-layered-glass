# Version 0.4 architecture

Version 0.4 replaces the required analytic scene proxy with a static triangle ray scene while retaining the 0.3 optical traversal model.

## Goals

The first BVH stage addresses two limitations of 0.3:

1. Opaque objects no longer require manual blocker registration.
2. Glass geometry no longer needs to be declared as a box, rounded box, or sphere.

The implementation targets static `BufferGeometry` and static GLB scenes.

## Frame pipeline

```text
normal Three.js scene, glass excluded
  → base color + opaque depth
  → rasterized glass coverage mask
  → reduced-resolution BVH resolver inside the mask
  → full-resolution base/glass composite
  → foreground transparency
  → output / post-processing
```

Opaque meshes keep their normal Three.js materials, shadows, and raster path. Their triangles are also copied into the ray scene so a refracted world-space ray can terminate at the correct opaque surface.

## Ray-scene extraction

`RaySceneBuilder` traverses visible `Mesh` objects and classifies each material group:

```text
LayeredGlassMaterial     → glass
non-transparent opacity 1 → opaque
other transparent material → ignored
explicit override          → override wins
```

The builder generates one non-indexed world-space `BufferGeometry`. Every source triangle is expanded to three unique vertices so metadata remains attached to the triangle even when the BVH changes its index order.

Generated attributes:

```text
position       world-space vertex position
normal         world-space smooth normal
rayMeta        surface kind, volume ID, glass mode, material side
rayOpticalA    IOR, roughness, attenuation distance, reflection strength
rayOpticalB    attenuation color, dispersion
rayOpticalC    refraction reach, body tint, thin thickness
rayBaseColor   opaque fallback color and roughness
```

Material arrays and geometry groups are classified per triangle. A mesh can therefore contain both opaque and glass material groups.

## Acceleration structure

The flattened geometry is passed to `three-mesh-bvh` with an indirect SAH build. `MeshBVHUniformStruct` and vertex-attribute textures copy the BVH, positions, normals, and metadata into GPU-readable textures.

The default worker build transfers only the generated static position and index buffers. If worker generation fails, the builder regenerates the flattened geometry before falling back to a main-thread build, avoiding detached-buffer errors.

## Fragment traversal

Every covered fragment reconstructs a world-space camera ray and calls `bvhIntersectFirstHit` repeatedly.

```text
nearest hit
  opaque → terminate at the exact world-space hit
  thin glass → apply a finite slab approximation and continue
  volume glass → update medium stack, refract, and continue
```

The medium stack stores volume ID, IOR, attenuation color, and attenuation distance. Exit hits pop the matching volume rather than assuming every exit is always the top item.

### Dispersion

Medium and high quality evaluate red, green, and blue paths with different IOR values at every interface. Dispersion therefore affects geometry behind multiple layers, not only the terminal color sample.

### Rough transmission

Roughness perturbs entry and exit normals for each path. High quality evaluates two deterministic rough paths per spectral channel. Terminal sampling also uses a roughness-dependent screen-space filter.

### Opaque shading

If the exact opaque hit projects to the same raster depth as the base render, the resolver reuses the normally shaded base color. If the hit is off-screen or hidden in the original camera render, the resolver falls back to the material base color and a simple environment response.

This fixes ordering and provides a stable first-stage result without implementing a full duplicate Three.js material evaluator in the ray shader.

## Coverage mask

The expensive fullscreen material first samples a low-cost coverage texture. The coverage pass renders only material groups using `LayeredGlassMaterial`; opaque groups in mixed meshes are replaced with a color/depth-disabled skip material.

The mask avoids BVH traversal for pixels outside glass silhouettes. Opaque depth and the first BVH hit reject glass hidden behind ordinary opaque geometry. The expensive ray result can use a reduced resolution, but a separate full-resolution composite preserves the normal opaque scene outside glass coverage.

## Scene synchronization

Two signatures are tracked:

- **geometry signature:** mesh topology, transforms, visibility classification, draw ranges, and groups;
- **material signature:** optical parameters and opaque fallback values.

Geometry changes trigger BVH preparation. Material-only changes update metadata attribute textures without rebuilding the BVH when surface classification is unchanged.

`sceneSync: 'manual'` disables signature comparison for large scenes that already have an explicit invalidation workflow.

## Backends

```text
auto     analytic preparation fallback, then BVH
bvh      real static triangles and automatic opaque intersections
analytic 0.3 primitive resolver
legacy   0.2 back-face / ping-pong classes exposed separately
```

Analytic proxy properties remain on the material only for compatibility and explicit analytic optimization. They are not used by the BVH backend.

## Quality presets

```text
low     0.5 resolution, 1 path, 4 traversals, BVH leaf size 4
medium  0.75 resolution, RGB paths, 8 traversals, leaf size 2
high    1.0 resolution, RGB × 2 rough paths, 12 traversals, leaf size 1
```

The values are compile-time shader limits when the composer is constructed.

## Static-stage limitations

- World-space triangles are baked at preparation time.
- Rigid transforms require a rebuild.
- Instancing, batching, live skinning, and live morph deformation are not part of stage one.
- Closed volume behavior depends on manifold geometry and consistent winding.
- Transparent materials other than `LayeredGlassMaterial` are not added as opaque ray blockers.

A future BLAS/TLAS backend can preserve the same shader material model while updating rigid object transforms without flattening the complete scene again.
