# Migrating from 0.2 to 0.3

Version 0.2 rendered each glass mesh separately. It captured that mesh's back faces, sampled the color accumulated behind it, and swapped two render targets after every object. This worked well for controlled camera angles, but every glass mesh still received one global back-to-front position.

Version 0.3 resolves all registered analytic volumes in one fullscreen pass. Each pixel independently finds its nearest volume, refracts through the volume, and continues from the resulting world-space ray. No object sort is involved.

## Architecture comparison

| Concern | 0.2 | 0.3 |
| --- | --- | --- |
| Glass ordering | One global order per mesh | Nearest intersection per pixel |
| Glass behind glass | Ping-pong color composition | Continuous world-space ray traversal |
| Opaque/glass overlap | Opaque scene flattened before glass | Registered blockers share the same intersection list |
| Geometry | Arbitrary closed meshes | Box, rounded box, sphere / transformed sphere |
| Back-face buffers | Two floating-point passes per glass mesh | None |
| Dispersion | RGB offset at the final source sample | Separate spectral path through every interface |
| Rough transmission | Final texture blur | Interface-normal perturbation plus terminal blur |
| Mobile requirements | WebGL2 + float color attachments | WebGL2; byte color-target fallback available |
| Cost scaling | Draw passes per glass object | Fragment traversal × active volumes |

## Basic material migration

The optical properties remain the same. Add an analytic shape when it cannot be inferred:

```js
const material = new LayeredGlassMaterial({
  shape: 'roundedBox',
  radius: 0.1,
  ior: 1.48,
  roughness: 0.05,
  attenuationColor: '#8bcfff',
  attenuationDistance: 1.15,
  refractionReach: 2.1,
  reflectionStrength: 1.85,
  dispersion: 0.006,
});
```

`BoxGeometry` and `SphereGeometry` are inferred automatically. Add `shape: 'roundedBox'` and `radius` when using `RoundedBoxGeometry` or a box-like GLB mesh.

## Register opaque blockers

Opaque meshes still use their normal Three.js materials. Registration adds only an analytic intersection proxy:

```js
const opaquePanel = new THREE.Mesh(
  geometry,
  new THREE.MeshPhysicalMaterial({ color: '#ff8b74' }),
);

composer.addBlocker(opaquePanel, {
  shape: 'roundedBox',
  radius: 0.1,
});
```

Or mark the object for automatic discovery:

```js
setLayeredGlassBlocker(opaquePanel, {
  shape: 'roundedBox',
  radius: 0.1,
});
```

Only opaque objects that need exact ordering along refracted paths need blocker registration. Other opaque scene geometry remains available through the base color/depth fallback.

## Keep the old renderer

Use the explicit legacy class for arbitrary closed meshes:

```js
const composer = new LegacyLayeredGlassComposer(renderer);
```

The legacy pipeline retains back-face buffers and object sorting. It does not provide the order-independent guarantees of the analytic 0.3 compositor.
