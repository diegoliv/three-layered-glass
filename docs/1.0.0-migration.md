# Migrating from 0.4 to 1.0

Version 1.0 keeps the 0.4 static-BVH rendering model and optical output. The breaking changes organize imports around the common path and remove deprecated APIs from primary entrypoints.

## Primary Three.js API

These imports do not change:

```js
import {
  LayeredGlassComposer,
  LayeredGlassMaterial,
  supportsLayeredGlass,
} from 'three-layered-glass';
```

The primary entrypoint now contains only those three runtime exports.

## Advanced imports

Move backend-specific classes, diagnostics, constants, and quality primitives:

```diff
- import {
-   BVHLayeredGlassComposer,
-   LayeredGlassAdaptiveQuality,
-   LayeredRayScene,
-   RaySceneBuilder,
-   QUALITY_PRESETS,
- } from 'three-layered-glass';
+ import {
+   BVHLayeredGlassComposer,
+   LayeredGlassAdaptiveQuality,
+   LayeredRayScene,
+   RaySceneBuilder,
+   QUALITY_PRESETS,
+ } from 'three-layered-glass/advanced';
```

The advanced entrypoint also contains `AnalyticLayeredGlassComposer`, ray visibility constants, quality resolution helpers, and the float-target capability check.

The primary `LayeredGlassComposer` type now exposes the common static-scene controls. If existing vanilla code configures a backend, custom target behavior, foreground layers, or shader traversal limits, import the same runtime class from advanced:

```diff
- import { LayeredGlassComposer } from 'three-layered-glass';
+ import { LayeredGlassComposer } from 'three-layered-glass/advanced';
```

## EffectComposer

```diff
- import { LayeredGlassPass } from 'three-layered-glass';
+ import { LayeredGlassPass } from 'three-layered-glass/postprocessing';
```

Its behavior and constructor are unchanged.

## Legacy imports

Move 0.2/0.3 compatibility classes and blocker helpers:

```diff
- import {
-   LayeredGlassRenderer,
-   LegacyLayeredGlassComposer,
-   LegacyLayeredGlassPass,
-   sortGlassObjectsBackToFront,
- } from 'three-layered-glass';
+ import {
+   LayeredGlassRenderer,
+   LegacyLayeredGlassComposer,
+   LegacyLayeredGlassPass,
+   sortGlassObjectsBackToFront,
+ } from 'three-layered-glass/legacy';
```

New code should use `LayeredGlassComposer`. The legacy subpath exists to make migration explicit, not as an alternative starting point.

## Simpler R3F composition

The recommended 0.4 examples wrapped the scene and often used the convenience mesh:

```jsx
<LayeredGlassComposer
  backend="bvh"
  quality="medium"
  worker
  renderPriority={1}
>
  <LayeredGlass materialProps={{ roughness: 0.05 }}>
    <torusKnotGeometry />
  </LayeredGlass>
</LayeredGlassComposer>
```

The 1.0 common path relies on defaults and standard material composition:

```jsx
<>
  <LayeredGlassComposer />

  <mesh>
    <torusKnotGeometry />
    <LayeredGlassMaterial roughness={0.05} />
  </mesh>
</>
```

`LayeredGlass` remains exported from `three-layered-glass/r3f`, so existing convenience-mesh code can continue to run.

## R3F primary and advanced props

The primary TypeScript surface intentionally exposes only:

- `enabled`;
- `quality`;
- `adaptive`;
- `onProgress`, `onReady`, and `onError`;
- optional provider children.

If existing code uses `backend`, `renderPriority`, custom targets, scene overrides, traversal limits, or manual synchronization props, change only the import:

```diff
- import { LayeredGlassComposer } from 'three-layered-glass/r3f';
+ import { LayeredGlassComposer } from 'three-layered-glass/r3f/advanced';
```

The runtime component is the same; the advanced subpath exposes its complete integration type.

## R3F hooks and passes

The material hook stays in the primary entrypoint:

```js
import { useLayeredGlassMaterial } from 'three-layered-glass/r3f';
```

Imperative composer and visibility hooks move to advanced:

```diff
- import {
-   useLayeredGlassComposer,
-   useLayeredGlassRayVisibility,
- } from 'three-layered-glass/r3f';
+ import {
+   useLayeredGlassComposer,
+   useLayeredGlassRayVisibility,
+ } from 'three-layered-glass/r3f/advanced';
```

The R3F EffectComposer bridge moves to its own subpath:

```diff
- import { LayeredGlassEffectPass } from 'three-layered-glass/r3f';
+ import { LayeredGlassEffectPass } from 'three-layered-glass/r3f/postprocessing';
```

Deprecated blocker helpers move to legacy:

```diff
- import {
-   LayeredGlassBlocker,
-   useLayeredGlassBlocker,
- } from 'three-layered-glass/r3f';
+ import {
+   LayeredGlassBlocker,
+   useLayeredGlassBlocker,
+ } from 'three-layered-glass/r3f/legacy';
```

Ordinary opaque meshes need no wrapper.

## Preparation state and errors

Version 1.0 adds a declarative preparation hook:

```jsx
function Status() {
  const { status, progress, error, ready } = useLayeredGlass();
  return null;
}

<LayeredGlassComposer>
  <Status />
  <Scene />
</LayeredGlassComposer>
```

It also adds:

```jsx
<LayeredGlassComposer
  onError={(error, composer) => reportError(error)}
/>
```

Changing the identity of `onReady`, `onProgress`, `onError`, or `onCreated` no longer starts a new static BVH build. Preparation completion and failure now invalidate an R3F Canvas, including `frameloop="demand"`.

## Adaptive quality

The R3F wrapper can own the existing resolution controller:

```jsx
<LayeredGlassComposer adaptive />
```

or:

```jsx
<LayeredGlassComposer
  adaptive={{ minScale: 0.45, maxScale: 0.7 }}
/>
```

Vanilla Three.js can continue importing `LayeredGlassAdaptiveQuality` from the new advanced subpath.

## Material typing

The R3F material now accepts the safe standard `ShaderMaterial` prop surface in addition to layered-glass optical props. Internal shader source, uniforms, blending, opacity, depth, and tone-mapping configuration remain protected because the compositor owns those invariants.

## Node and validation

Version 1.0 requires Node 20.19 or newer, matching the current Vite toolchain. The release check no longer relies on the newer `import.meta.dirname` convenience property and remains portable across supported runtimes.

After updating imports, run:

```bash
npm run check
npm test
```
