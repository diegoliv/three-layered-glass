# Migrating from 0.3 to 0.4

Version 0.4 makes the real static scene geometry the default source of ray intersections.

## Remove analytic shape declarations

Version 0.3:

```js
const material = new LayeredGlassMaterial({
  shape: 'roundedBox',
  radius: 0.08,
  ior: 1.48,
});
```

Version 0.4:

```js
const material = new LayeredGlassMaterial({
  ior: 1.48,
});
```

`shape`, `radius`, `halfExtents`, and `center` remain available only for `backend: 'analytic'` and migration compatibility.

## Remove blocker registration

Version 0.3:

```js
composer.addBlocker(opaqueMesh, {
  shape: 'roundedBox',
  radius: 0.08,
});
```

Version 0.4:

```js
scene.add(opaqueMesh);
```

Visible ordinary opaque meshes are automatically included in the static ray scene.

Use opt-out overrides for helpers, overlays, or geometry that should not participate:

```js
composer.setRayVisibility(helper, 'ignore');
```

## Prepare the static scene

```js
const composer = new LayeredGlassComposer(renderer, {
  backend: 'auto',
  quality: 'medium',
  worker: true,
});

await composer.prepare(scene);
```

`autoPrepare` can begin this step from the first render call, but explicit preparation makes loading state and progress predictable.

## GLB workflow

```js
const gltf = await loader.loadAsync('/model.glb');
scene.add(gltf.scene);

const glass = gltf.scene.getObjectByName('Glass');
glass.material = new LayeredGlassMaterial({
  ior: 1.5,
  roughness: 0.03,
  attenuationColor: '#d9f2ff',
});

await composer.prepare(scene);
```

No shape proxy is needed. Volume meshes should be closed and consistently wound.

For single-surface glass:

```js
glass.material = new LayeredGlassMaterial({
  mode: 'thin',
  thickness: 0.012,
});
```

## Updating the scene

Geometry or transform changes:

```js
object.position.x += 1;
composer.invalidateGeometry(object);
await composer.prepare(scene);
```

Optical material changes:

```js
material.ior = 1.52;
composer.invalidateMaterial(mesh);
```

With `sceneSync: 'auto'`, both are detected. Material-only updates refresh metadata without rebuilding triangle bounds.

## R3F

Version 0.3:

```jsx
<LayeredGlassComposer>
  <LayeredGlass materialProps={{ shape: 'sphere' }} />
  <LayeredGlassBlocker>{/* opaque mesh */}</LayeredGlassBlocker>
</LayeredGlassComposer>
```

Version 0.4:

```jsx
<LayeredGlassComposer backend="bvh" quality="medium" worker>
  <LayeredGlass materialProps={{ ior: 1.48 }}>
    <torusKnotGeometry />
  </LayeredGlass>

  <mesh>
    <boxGeometry />
    <meshStandardMaterial color="orange" />
  </mesh>
</LayeredGlassComposer>
```

Use `useLayeredGlassRayVisibility(ref, 'ignore')` for explicit exclusions.

## Keeping the analytic backend

For small primitive scenes where manually controlled proxies are acceptable:

```js
const composer = new LayeredGlassComposer(renderer, {
  backend: 'analytic',
});
```

The analytic backend remains faster for a small number of boxes and spheres, but it retains its proxy and blocker requirements.

## Unsupported dynamic geometry

The 0.4 BVH stage intentionally excludes:

- `InstancedMesh` and `BatchedMesh`;
- continuously skinned meshes;
- live morph deformation;
- topology modified every frame.

Use the normal fallback while preparing, or remain on the analytic/legacy backend for those cases. A future two-level BVH stage will target rigid transform updates.
